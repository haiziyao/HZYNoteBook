# 企业智能知识库管理系统——简历包装

## 项目名称

企业智能知识库管理系统

## 项目角色

后端核心模块开发（根据实际参与范围调整为“后端开发”或“核心开发”）

## 项目描述

面向企业内部知识沉淀与复用的智能知识库平台，覆盖文档管理、审核发布、全文检索、RAG 智能问答和 KAG 知识图谱探索。系统采用微服务架构，将文档元数据、正文、检索索引和知识图谱分开管理，重点解决企业文档“难管理、难检索、难关联、难复用”的问题。

## 技术栈

Java 21、Spring Boot、Spring Cloud Gateway、Spring Cloud Alibaba、Nacos、OpenFeign、MyBatis-Plus、MySQL、MongoDB、Redis、Elasticsearch、Neo4j、RabbitMQ、LangChain4j、CompletableFuture、WebSocket/STOMP、RustFS、React、TypeScript。

## 核心工作与项目亮点

1. **参与企业知识库微服务架构设计与核心链路开发。** 按业务边界拆分用户认证、文档管理、文件管理、AI、搜索、知识图谱、统计、基础服务和网关等服务；通过 Nacos 完成服务注册与发现，使用 OpenFeign 处理需要返回值的同步调用，使用 RabbitMQ 解耦审核通知、索引构建等异步任务；网关统一承担 JWT 鉴权、路由和请求入口管理。

2. **实现基于 Elasticsearch 的 RAG 混合检索链路。** 对审核通过的文档按 Markdown 标题、段落和句子边界进行分块，并为 Chunk 生成 Embedding；查询阶段并行执行 BM25 关键词检索和 dense_vector kNN 向量检索，使用 RRF（C=60）融合排序，再通过 LLM 对候选 Chunk 进行相关性重排，最终将高相关片段注入 Prompt 生成答案；Embedding 或检索异常时支持 BM25-only 等降级路径。

3. **实现 Neo4j 知识图谱与 RAG 的 KAG 融合检索。** 在 `GraphBuildServiceImpl` 中按文档重新分块，逐 Chunk 调用 LLM 抽取实体和关系，经过 `EntityNormalizer` 做同名、别名和编辑距离相似度归一化后写入 Neo4j，建立 Document→Chunk→KnowledgeEntity 关联；在线查询时由 LLM 提取问题实体，在 Neo4j 中进行最多 2 跳关系遍历并反向查找关联 Chunk，再与 RAG 结果合并，为需要跨文档关联和路径推理的问题提供图谱上下文。

4. **设计审核发布与通知的事件驱动闭环。** 文档在草稿、待审核、已发布等状态间流转；审核提交、通过、驳回由 `kb-document` 发布 RabbitMQ 事件，`kb-foundation` 的 `ReviewNotificationListener` 消费后先将通知持久化到 MySQL，再通过 WebSocket/STOMP 推送给在线用户，离线用户可通过通知查询接口补偿获取；审核通过后的 RAG、KAG、ES 索引构建采用异步触发，避免阻塞主审核请求。

## 一句话项目介绍

我参与开发的是一个以企业知识检索为核心的微服务知识库系统：文档经过审核后被分块、向量化并写入 Elasticsearch，同时抽取实体关系构建 Neo4j 图谱；用户提问时融合 BM25、向量检索、图谱路径和 LLM 重排结果，再交给大模型生成有知识库依据的回答。

## 面试展开顺序

建议按以下顺序讲，主线最清晰：

1. 为什么按业务边界拆分微服务，以及 Feign、RabbitMQ 分别解决什么问题；
2. 文档审核通过后，分块、Embedding、ES 索引和 Neo4j 建图如何异步衔接；
3. RAG 的 BM25 + kNN + RRF + LLM 重排完整链路；
4. KAG 如何从实体抽取、实体归一化、图遍历得到关联 Chunk，并和 RAG 融合；
5. 索引构建失败、Embedding 不可用、用户离线时分别如何降级或补偿。
