# 项目初衷

### 不满于现状
对于目前 小型 机器人社团中,视觉组 的生态位遭到挤压, 甚至有些组通过一些模块来替代完全取缔视觉组. 这是一种好的"演化"吗?

我的回答: 是也不是.

对于一些简单的任务,有可能我们的电控成员学一些openMV,就能够解决不少的问题.但是对于一些多任务型,过于"轻视"视觉组往往会造成一些"资源浪费"或者"南辕北辙".

视觉是辅助没错,但不能过于挤压视觉组的生态位.

### 更大的隐患
目前对于视觉组培训来说,我是极其不满意的,对于新人来说,如果没有"老人"对这个项目所用到技术的说明,那么新人必定从0造轮子,由于目前AI盛行,不难发现,这些新人做的东西都是"一坨能运行的屎".

没有任何规范可言.

### Coding is Cheap, But Promgrame is not.
目前AI时代,对于一些新人,他不需要任何业务学习成本,只需要下载Agent coding tool,就可以完成任务, "完成功能"似乎就"enough".

但是,程序绝对不是这样的.一个可靠的程序更不是这样的.

### 我的畅想
所以针对这种情况,我们改变不了什么,但也能做点什么.

既然功能开发是easy,系统是困难的,那我们就不妨把系统封装起来.

于是,RuboVision诞生了


# 项目开发

### core
在coding is cheap的时代,手写代码还有意义吗?

我不太清楚,但是我手动实现了框架core的整个定义和状态转移.

开发了source->listener->dispatcher->executor整个链路,明确了项目需求,确定了技术难点.

###  core-vision
之后由于时间需求,大多数代码由 codex 开发完成. 功能完善.

### bug written by Codex?
功能实现完成之后,对于这样一个框架类项目,那么最重要的就是性能,

但是,出现了一些严重的问题.首次测试CPU占用率高达260%, 原因是:

在串口通信和GPIO对应端口连接上,codex实现了一个死循环,只要开启功能,没连上就继续重新连接,loop循环.

自然占用了2H的CPU,导致严重的性能问题.对于内存占用,在一个合理区间,十几M.

对于其他性能问题,还没有来得及排查,但是之后一定会重新检查整个项目.
果然,让Agent进行自我评分还是太难崩了,怎么能让自己给自己打分呢 ? !

这个话题应该轮不到我来评价.

rust是一门非常优秀的语言,有着"现代"的编译器.对于我来说,rust可能成为我终生喜欢的语言,为什么?语法很有兴趣,能做的事情很多,这里有情怀的人也很多.

我相信随着人工智能浪潮平稳,py热度褪下之后,Rust将会随着具身智能的兴起而在时代中有立足之地.
为什么?
Coding is cheap. Rust的唯一劣势恰好是 Coding is difficult.
