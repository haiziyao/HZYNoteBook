# WebSocket 记录：在线通知通道

## 业务定位

WebSocket 只负责实时传输，不负责保存消息。通知记录先落 MySQL，WebSocket 发送失败或用户离线时，用户仍可通过未读消息接口补拉。

## 审核场景

```text
提交审核
→ 选定在线审核员
→ 通知入库
→ WebSocket 推送审核任务
→ 审核员处理
→ 审核结果通知用户
```

没有合适审核员时，代码走降级策略（例如转管理员/待处理队列），不能把 WebSocket 在线状态当作审核成功条件。

## 面试坑点

- 连接断开、重复连接、心跳和鉴权必须考虑。
- 推送成功不等于业务处理成功；业务状态以数据库记录为准。
- 在线推送与离线补偿共同组成可靠通知方案。
