# 面经资料库

本目录用于保存真实面试经历，原始记录尽量保留面试现场信息；从这些记录中提炼出的知识点统一沉淀到上级目录的 [面试补漏](../面试补漏/README.md)。

## 推荐工作流

1. 面试结束后，先在对应月份目录记录公司、岗位、时间、面试形式和原始题目。
2. 按本文档的“双区格式”整理：前半部分只放题目，后半部分再放题目与解答。
3. 将题目按 Java 基础、JUC、Redis、系统设计、场景题等分类，扩展到 `面试补漏` 的专题文件。
4. 每次补充后更新对应目录 README 的“文件清单”和更新时间。
5. 复习时先跳过答案区自测，再展开答案区核对；不确定的答案标记为“待验证”，不要凭印象写成结论。

每份面经文件统一分为两大部分：先列题目，再写题目对应的解答。

## 一、题目清单

只列出实际遇到的面试题，不写答案、分析或提示，方便直接复制和分享。

```markdown
## 一、题目清单

1. 题目一
2. 题目二
3. 题目三
```

## 二、题目与解答

按照上面的编号逐题补充答案，题目顺序必须保持一致。答案以简短、准确、便于复习为主。

```markdown
## 二、题目与解答

### 1. 题目一

答案：

### 2. 题目二

答案：
```

## 命名建议

面经文件建议使用以下格式：

```text
年份-月份-公司-岗位.md
```

例如：

```text
2026-09-小红书-Java实习.md
```

## 编写要求

- 第一部分只能有题目，不能混入答案或解析。
- 第二部分必须使用与第一部分一致的题号。
- 一道面试题单独编号，不要把多个独立问题合并成一道题。
- 录音转写中的明显错词可以根据上下文修正；无法确认的内容标注“待确认”。
- 答案优先写结论，再补充必要的实现方式或关键点。
- 建议在文件元数据中维护 `review_status`、`last_reviewed`、`review_count`，便于“面试复习”技能筛选未复习面经。
