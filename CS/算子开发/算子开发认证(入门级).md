### AI Core: 达芬奇架构 
* 计算单元(矩阵,向量,标量)
* 存储系统
* 控制单元

``` bash
AI Core
├── 计算单元
│   ├── Scalar 单元
│   ├── Vector 单元
│   └── Cube 单元
├── 存储单元
│   ├── L1 Buffer
│   ├── L0A / L0B / L0C
│   ├── Unified Buffer
│   ├── BT Buffer
│   └── FP Buffer
└── 控制单元
    ├── ICache
    ├── Instruction Dispatch
    ├── Cube Queue
    ├── Vector Queue
    ├── MTE Queue
    └── Event Sync
```


**A1 系列**: 耦合架构, AIC和AIV耦合
**A2 系类**: AIC和AIV独立,解耦,通过Global Memory传递数据, 比耦合多了两个 Buffer, BT buffer, FP Buffer

Scalar单元(小cpu):
1. 标量数据运算
2. 指令发射
3. 流程控制
4. 循环控制
5. 分支判断
6. 地址和参数计算
7. 控制 Cube / Vector / MTE 等单元执行

>不要把大量 if/else、复杂变量计算、复杂循环逻辑放到 Scalar 上。

Vector单元:Vector 负责执行向量运算，类似 SIMD
Cube单元: Cube 单元负责执行矩阵运算，尤其是矩阵乘。

Block Dim 逻辑核: 启动多少个逻辑核并行执行(类似于多线程的概念)
耦合架构: BlockDim = 启动多少个 AI Core
分离架构:
1. 只包含 Vector 计算的算子：BlockDim 设置启动多少个 AIV 实例
2. 只包含 Cube 计算的算子：BlockDim 设置启动多少个 AIC 实例
3. Vector/Cube 融合计算的算子：BlockDim 设置启动多少个 AIV + AIC 组合


存储单元:

| 存储单元                | 作用                          | 例子                    |
| ------------------- | --------------------------- | --------------------- |
| L1 Buffer           | AI Core 内较大的数据中转区           | 从 GM 搬来的 A/B 先放这里     |
| L0A Buffer          | Cube 左输入                    | 矩阵 A                  |
| L0B Buffer          | Cube 右输入                    | 矩阵 B                  |
| L0C Buffer          | Cube 输出/累加结果                | A×B 的中间结果/最终结果        |
| Unified Buffer / UB | Vector 和 Scalar 的输入输出区      | 向量加法、ReLU、Softmax 的数据 |
| BT Buffer           | BiasTable Buffer，存 bias     | A×B+bias 的 bias       |
| FP Buffer           | FixPipe Buffer，存量化/ReLU 参数等 | int8 量化参数、ReLU 参数     |

AI Core 搬运单元：MTE / FixPipe

```
MTE1负责内部搬运，例如：
L1 -> L0A / L0B
L1 -> UB
L1 -> FP Buffer
L1 -> BT Buffer

MTE2负责从 GM 搬到内部缓存，例如：
GM -> L1
GM -> L0A / L0B
GM -> UB

负责把内部数据写回 GM，例如：
UB -> GM
L1 -> GM

FixPipe 负责 L0C -> {GM / L1}
搬运过程中可以完成随路格式/类型转换
```

AI Core 控制单元：队列和同步

## 背诵版本

1. Ascend AI 处理器由 Control CPU、AI Core、AI CPU、缓存、DVPP、I/O 等组成。

2. AI Core 是计算核心，也叫 DaVinci Core。

3. AI Core 计算单元有 Scalar、Vector、Cube：
   Scalar 管控制，
   Vector 算向量，
   Cube 算矩阵。

4. Vector 的数据在 UB。

5. Cube 的 A 在 L0A，B 在 L0B，结果在 L0C，bias 在 BT Buffer。

6. L1 是通用中转缓存，UB 是 Vector 工作区。

7. MTE 是搬运单元：
   MTE2 负责 GM 到片上，
   MTE1 负责 L1 到内部 Buffer，
   MTE3 负责写回 GM，
   FixPipe 负责 L0C 结果输出。

8. 耦合架构：Cube 和 Vector 在一起。
   分离架构：AIC 管 Cube，AIV 管 Vector。

9. BlockDim 是启动多少个逻辑核并行执行。

10. Cube Queue、Vector Queue、MTE Queue 可以并行，Event Sync 负责同步。

## 算子开发编程

Ascend C 编程 = SPMD 多核并行 + Kernel 函数 + 数据搬运 + 流水线 + 硬件抽象


核函数:

``` C++
extern "C" __global__ __aicore__
void add_custom(__gm__ uint8_t* x, __gm__ uint8_t* y, __gm__ uint8_t* z);
```

|函数类型|在哪里执行|作用|
|---|---|---|
|host 函数|CPU / 主机侧|准备数据、分配内存、启动 kernel|
|kernel 函数|AI Core / Device 侧入口|每个核执行的主函数|
|device 函数|AI Core / Device 侧普通函数|被 kernel 调用的辅助函数|


GlobalTensor：表示 Global Memory 上的数据
LocalTensor：表示 Local Memory 上的数据
TPosition：表示逻辑存储位置
TQue：队列
TPipe：流水线管理

总结:
1. Ascend C 使用 SPMD 编程模型：
   所有 AI Core 执行同一份代码，但处理不同数据。

2. blockDim 表示启动多少个逻辑核。

3. GetBlockIdx() 返回当前核的 block_idx，用来区分每个核负责的数据区间。

4. 数据切分的典型公式：
   start = GetBlockIdx() * BLOCK_LENGTH

5. 如果不加 block_idx 偏移，所有核会重复处理同一块数据。

6. Kernel 函数是 AI Core 上执行的入口函数。

7. Kernel 函数常见声明：
   extern "C" __global__ __aicore__ void kernel_name(...)

8. __global__ 表示这是核函数，可以被 <<<...>>> 调用。

9. __aicore__ 表示函数在 AI Core 上执行。

10. __gm__ 表示指针指向 Global Memory。

11. 核函数调用格式：
    kernel<<<blockDim, l2ctrl, stream>>>(args...)

12. kernel 调用是异步的，需要 aclrtSynchronizeStream(stream) 等待执行完成。

13. Ascend C 中函数分为：
    host 侧函数、kernel 函数、device 侧函数。

14. GlobalTensor 表示 Global Memory 上的数据。

15. LocalTensor 表示 Local Memory 上的数据。

16. TPosition 用逻辑位置抽象底层物理存储，如 GM、VECIN、VECCALC、VECOUT、A1、A2、B1、B2、CO1 等。

17. DataCopy 负责 Global Memory 和 Local Memory 之间的数据搬运。

18. Vector / Cube 负责真正计算。

19. Queue 通过 EnQue / DeQue 实现流水阶段之间的数据同步。

20. AllocTensor / FreeTensor 负责 LocalTensor 的申请、释放和复用同步。

21. 流水任务把处理拆成 CopyIn、Compute、CopyOut，让搬运和计算重叠，提高性能。

22. DataCopyParam 用于非连续数据的多块搬运，包括 blockCount、blockLen、srcStride、dstStride 等参数。

## 昇腾异构编程基础

Vector 编程范式：适合逐元素向量计算
Cube 编程范式：适合矩阵乘、卷积这类矩阵计算
MIX 融合算子范式：Cube + Vector 连起来做融合计算

### Vector
对一段 Tensor 中的很多元素做同类操作。
```
Abs
Add
Sub
Mul
Div
ReLU
LeakyReLU
Exp
Log
Softmax 的部分步骤
```

CopyIn → Compute → CopyOut

``` c
void CopyIn()
{
    auto tensor = queIn.AllocTensor<half>();
    AscendC::DataCopy(tensor, gm, len);
    queIn.EnQue(tensor);
}

void Compute()
{
    auto tensorIn = queIn.DeQue<half>();
    auto tensorOut = queOut.AllocTensor<half>();

    AscendC::Abs(tensorOut, tensorIn, 1024);

    queIn.FreeTensor(tensorIn);
    queOut.EnQue(tensorOut);
}

void CopyOut()
{
    auto tensor = queOut.DeQue<half>();
    AscendC::DataCopy(gmOut, tensor, 1024);
    queOut.FreeTensor(tensor);
}
```


### Cube
矩阵乘 MatMul
卷积 Conv
GEMM
Attention 里的 QK^T、PV

CopyIn → Split → Compute → Aggregate → CopyOut

``` c
//高级库 Matmul
matmulObj.SetTensorA(aGlobal);
matmulObj.SetTensorB(bGlobal);
matmulObj.SetBias(biasGlobal);

matmulObj.Iterate();

matmulObj.GetTensorC(cGlobal);
```

### MIX
一个算子里同时用 Cube 和 Vector

```
MatMul + Bias + ReLU
MatMul + LeakyReLU
MatMul + Add + LayerNorm
MatMul + Softmax 的部分流程
Attention 中 Cube 和 Vector 混合
```

``` c
REGISTER_MATMUL_OBJ(...);
matmulObj.Init(&tiling);

matmulObj.SetTensorA(aGlobal);
matmulObj.SetTensorB(bGlobal);
matmulObj.SetBias(biasGlobal);

while (matmulObj.Iterate()) {
    auto reluOutLocal = reluOutQueue.AllocTensor<cType>();

    matmulObj.GetTensorC(reluOutLocal, false, true);

    AscendC::LeakyRelu(
        reluOutLocal,
        reluOutLocal,
        alpha,
        len
    );

    reluOutQueue.EnQue(reluOutLocal);

    auto out = reluOutQueue.DeQue<cType>();
    AscendC::DataCopy(cGlobal[offset], out, copyParam);
    reluOutQueue.FreeTensor(out);
}

matmulObj.End();
```


### 总结

| 范式     | 适合什么             | 核心阶段                                           | 典型例子                             |
| ------ | ---------------- | ---------------------------------------------- | -------------------------------- |
| Vector | 逐元素向量计算          | CopyIn → Compute → CopyOut                     | Add、Abs、ReLU、Exp                 |
| Cube   | 矩阵计算             | CopyIn → Split → Compute → Aggregate → CopyOut | MatMul、Conv、GEMM                 |
| MIX    | Cube + Vector 融合 | Cube 结果接 Vector 或 Vector 结果接 Cube              | MatMul + ReLU、MatMul + LeakyReLU |
|        |                  |                                                |                                  |
1. Vector 编程范式用于向量/逐元素计算。

2. Vector 范式分为：
   CopyIn、Compute、CopyOut。

3. CopyIn 负责 GM → Local Memory。

4. Compute 负责在 Local Memory 中调用 Vector 指令计算。

5. CopyOut 负责 Local Memory → GM。

6. TPipe 是本核内资源管理器，负责 Queue 内存等资源管理。

7. TQue 是任务阶段之间传递 LocalTensor 的队列。

8. InitBuffer 用于给 Queue 分配 buffer，可用于 double buffer。

9. AllocTensor 用于申请 LocalTensor。

10. FreeTensor 用于释放 LocalTensor。

11. EnQue 表示数据准备好，交给下一阶段。

12. DeQue 表示从队列取数据，没准备好就等待。

13. Cube 编程范式用于矩阵计算。

14. Cube 范式分为：
    CopyIn、Split、Compute、Aggregate、CopyOut。

15. Split 是矩阵块切分。

16. Aggregate 是矩阵乘部分结果汇聚。

17. Matmul 高阶 API 封装了 Cube 底层复杂流程。

18. MIX 融合算子是 Vector 和 Cube 混合计算。

19. Cube 输出可以作为 Vector 输入：
    CO2 → VECIN。

20. Vector 输出可以作为 Cube 输入：
    VECOUT → A1 → A2，
    VECOUT → B1 → B2。

21. MIX 常用于 MatMul + Bias + ReLU / LeakyReLU 等融合算子。

22. 融合的核心收益是减少中间结果反复读写 GM，提高性能。

## 算子性能优化
1. 数据搬运优化
2. 内存性能优化
3. API 调用优化

``` c
// 减少使用for
for (i = 0; i < total / copywidth; i++) {
    AscendC::DataCopy(
        tensorIn[i * instride],
        tensorGM[i * gmstride],
        copywidth
    );
}

// 用 DataCopyParams 一次描述规则
DataCopyParams params;

params.blockCount = total / copywidth;
params.blockLen = copywidth / NUM_ELE_PERBLOCK;
params.dstStride = instride;
params.srcStride = gmstride;

AscendC::DataCopy(tensorIn, tensorGM, params);
```

搬运颗粒度:
单次搬运 16KB 以上：较好
单次搬运超过 64KB：更容易用满访存带宽

内存优化:
从 GM 向 Local Memory 搬数据时，GM 地址尽量做到 512B 对齐。
