# 延迟双删与缓存数据库一致性

> 来源：[小红书-电话面-2026-8-31晚上11点](../../../面经/2026-9-面试/小红书-电话面-2026-8-31晚上11点.md)  
> 首次整理：2026-09-01　|　掌握状态：待复习

## 一、题目清单

1. 延迟双删能保证缓存和 DB 绝对一致吗？
2. 多线程下如何保证缓存和 DB 时时刻刻一致？

## 二、题目与解答

### 1. 延迟双删能保证缓存和 DB 绝对一致吗？

答案：不能。延迟双删只能降低脏缓存概率，属于最终一致方案，无法消除删除失败、并发回填、写请求乱序和延迟窗口。

典型顺序是删除缓存 → 更新 DB → 等待 → 再次删除缓存。等待时间不是正确性证明；生产上还应配合可靠事件（Outbox/CDC/消息队列）、幂等重试、版本号、失败告警和 TTL 兜底。

### 2. 多线程下如何保证缓存和 DB 时时刻刻一致？

答案：在缓存和 DB 是两个独立存储的前提下，不能仅靠常规双写保证绝对一致。强一致需求应尽量只保留一个权威读写源，或用事务/锁把读写串行化并接受吞吐下降；如果业务允许最终一致，则采用 Cache-Aside 加可靠事件、重试、版本校验和对账补偿。

回答框架：一致性目标 → 权威数据源 → 更新顺序 → 并发控制 → 失败补偿 → 监控指标。
