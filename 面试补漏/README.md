# 面试补漏知识库

本目录用于把 [面经](../面经/README.md) 中出现的题目扩展成可长期复习的知识卡片。面经记录“遇到过什么”，本目录回答“应该掌握到什么程度”。

### 分类判定规则

- 问“语言规则/类型关系”放 Java 基础；问“注解如何生成代码”放注解与编译期。
- 问“Redis 命令、数据结构或持久化”放 Redis；问“防止重复提交/接口幂等”放场景题，即使实现使用 Redis。
- 问“缓存和 DB 的更新顺序、一致性等级、故障补偿”放系统设计，不放 JUC；只有问题核心是 Java 锁、线程可见性或线程协作时才放 JUC。
- 同一知识点只保留一个主文件，其他分类 README 只做链接索引，避免答案分叉。

## 单个知识文件的固定格式

每份知识文件必须按下面顺序组织，方便“先自测、后核对”：

1. **题目清单**：只列问题，不出现答案、提示或结论。
2. **题目与解答**：题号、题目文字必须与前半部分完全一致；答案先给结论，再给原理、实现、边界和追问。

文件开头可保留元信息（来源、首次整理日期、掌握状态），但不要把答案写进题目清单。

## 从面经到补漏的整理标准

- 一道面经题可以拆成多个知识文件，但每个文件要有清晰主题，避免把无关知识堆在一起。
- 事实、方案和个人取舍分开写；涉及“绝对一致”“一定保证”等表述时，必须说明前提和边界。
- 代码只保留能说明关键机制的最小片段，并写明线程安全、异常和过期等边界。
- 每个文件注明来源面经和最后更新日期；答案有疑问时标记“待验证”，复核后再改为结论。

## 推荐复习方式

1. 先读专题 README，明确本轮范围。
2. 只看每份文件的“题目清单”，口头作答并记录薄弱点。
3. 展开“题目与解答”，核对结论、关键机制和边界条件。
4. 对错题补充自己的项目例子，再回到 [面试模拟提问指南](面试模拟提问指南.md) 做一轮追问。
