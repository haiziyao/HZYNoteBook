# 面试模拟提问指南

这份文档用于把面经变成互动练习。面经输入统一放在 [面经学习](../面经学习/README.md) 和 [面经](../面经/README.md)；你可以把新的面经文件发给我，或直接说“面试复习：小红书电话面”，由 [面试复习技能](C:/Users/17542/.codex/skills/interview-review/SKILL.md) 按下面的流程提问。

## 一、开始前的约定

- 默认一次只问一个问题，等待你回答后再追问，不提前展示标准答案。
- “面试复习”会先扫描 `面经学习` 和 `面经`，按元数据筛选 `未复习` 面经；没有元数据的旧面经默认视为未复习。
- 你可以指定模式：`速问速答`（每题 1～2 分钟）、`深挖模式`（连续追问原理和边界）、`系统设计`（需求—方案—权衡—风险）。
- 你可以指定范围：某一家公司、某次面试、某个分类，或只练错题。
- 如果你希望语音交流，可以在支持语音的客户端开启语音对话；我会保持同样的“一问一答—反馈—追问”节奏。

## 二、标准模拟流程

### 1. 取题

优先使用面经文件的“题目清单”，按原顺序或随机抽题。若题目已经沉淀到 `面试补漏`，可从对应专题抽取扩展题，但会明确告诉你这是“原题”还是“追问题”。

### 2. 作答

你先独立回答。建议使用“结论 → 原理 → 实现/例子 → 边界”的顺序；不会的题直接说不会，不要猜测。

### 3. 反馈

我会从四个维度反馈：

| 维度 | 检查点 |
| --- | --- |
| 正确性 | 结论是否成立，是否混淆概念。 |
| 完整性 | 是否覆盖实现、并发、异常和边界。 |
| 表达 | 是否先说结论，能否在 1～2 分钟内讲清。 |
| 深度 | 是否能解释取舍，并结合项目经验。 |

### 4. 追问

追问只围绕你的回答展开，例如“为什么”“还有什么风险”“并发下会怎样”“如何验证”。系统设计题通常追问容量、故障、一致性、降级和监控。

### 5. 复盘

每轮结束输出：掌握度（熟悉/部分掌握/待补漏）、关键缺口、建议补充到哪个专题、下一轮优先级。

## 三、我会采用的提问模板

```text
【原题】……
请先用 1 分钟回答，不需要展开所有细节。

【追问】……

【反馈】
- 亮点：……
- 缺口：……
- 更好的答题顺序：……

【参考答案】仅在你回答后展示
```

## 四、可直接使用的指令

- `开始模拟：使用最近一份面经，速问速答。`
- `开始模拟：只问 Redis，深挖缓存一致性。`
- `继续追问刚才的题，不要先给答案。`
- `展示这道题的标准答案，并告诉我还缺哪些关键词。`
- `把刚才的薄弱点整理到面试补漏对应分类。`

## 五、语音练习建议

语音模式下建议每题先完整说完，再让我反馈；如果需要暂停思考，可以说“暂停”，需要跳过可以说“下一题”。技术名词、代码和数字容易被语音识别错，关键内容可在文字中补发，我会以文字为准。
