## 二、题目与解答

### 1. InnoDB 二级索引的叶子节点和非叶子节点分别存什么？

非叶子节点存索引键分隔值和子节点指针；叶子节点存二级索引列与主键值。查询非覆盖列时，再根据主键到聚簇索引读取整行，这一步称为回表。

### 2. 联合索引 `(a,b,c)` 如何组织？范围条件后的列还能怎样使用？

B+ 树按 `(a,b,c)` 的字典序组织。`a = 3 AND b > 2 AND c = 1` 通常用 `a` 等值定位、用 `b` 形成范围；`c` 通常不能继续缩小连续扫描范围，但可能参与索引条件下推或残余过滤。

### 3. 两个单列索引在 `a = 3 AND b = 2` 中如何使用？

优化器可能只选一个索引后过滤另一个条件，也可能使用 `index_merge` 求交集，或者判断全表扫描成本更低。高频组合条件通常需要评估联合索引，而不是假设两个单列索引一定同时使用。

### 4. 如何使用执行计划定位慢查询？

从慢查询日志或 Performance Schema 找 SQL，再用 `EXPLAIN`/`EXPLAIN ANALYZE` 检查 `key`、`key_len`、`type`、`rows`、`filtered`、回表、排序和临时表。然后从索引、SQL、返回列、分页、数据归档和锁等待等方面优化，并以真实数据压测验证。

### 5. 四种事务隔离级别分别解决哪些问题？

读未提交可能出现脏读、不可重复读和幻读；读已提交避免脏读；可重复读避免脏读和不可重复读；串行化提供最强隔离。InnoDB 的可重复读还通过 MVCC 快照及间隙锁/临键锁在常见场景中抑制幻读。

### 6. 事务执行失败并回滚时，undo log 和 redo log 分别做什么？

正常回滚主要依据 undo log 反向撤销修改并释放锁；undo 也服务于 MVCC。redo log 主要保证持久性和崩溃恢复，不是正常回滚的反向命令。单条 SQL 失败不一定自动回滚整个事务，整体回滚通常由应用或事务框架决定。
