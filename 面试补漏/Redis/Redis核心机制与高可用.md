## 二、题目与解答

### 1. Redis 的过期删除会删除 Key 吗？

会，但通常不是在 TTL 到期瞬间立即删除。Redis 结合惰性删除与后台主动过期检查：访问过期 Key 时清理，后台也会周期性采样并删除过期 Key。

### 2. 过期删除和内存淘汰有什么区别？

过期删除由 TTL 触发，只处理已经过期的数据；内存淘汰由 `maxmemory` 压力触发，可能删除尚未过期的 Key。

### 3. Redis 有哪些常见用途和数据结构？

String、Hash、List、Set、ZSet 可用于缓存、计数、对象、队列、集合和排行榜；Bitmap 适合签到等布尔状态，HyperLogLog 适合基数估算，Stream 支持消息 ID、消费者组和确认。向量检索需要说明使用的 Redis 版本、Vector Sets 或扩展模块。

### 4. ZSet 的底层结构、跳表复杂度和查询过程是什么？

小规模 ZSet 可能使用 listpack；达到阈值后通常使用字典与跳表。字典便于按 member 找 score，跳表用于按 score 排序和范围查询。跳表从高层向右、超过目标后下降，平均复杂度为 `O(log n)`。

### 5. 除了 Redis，还能怎样实现分布式锁？

MySQL 可使用行锁、唯一约束或命名锁；ZooKeeper 可使用临时节点和监听机制；etcd 基于 Raft，适合强一致协调。选择时比较一致性、故障语义、延迟、吞吐和运维成本。

### 6. `maxmemory` 为 1 GB、已使用 999 MB 时还能继续写吗？

取决于 `maxmemory-policy` 和实际写入大小。可淘汰策略会先淘汰符合条件的 Key；`noeviction` 会拒绝需要新增内存的写命令。还要预留内存碎片、复制缓冲区和系统开销。

### 7. Redis 有哪些高可用架构？

主从复制提供数据副本和读扩展；Sentinel 提供监控、故障检测、自动故障转移和地址发现；Cluster 提供数据分片、主从副本和故障转移。异步复制仍可能在故障切换窗口丢失少量写入。
