# 高并发购票系统

> 来源：[字节-后端一面-2026-8-31](../../面经学习/字节-后端一面-2026-8-31.md)  
> 首次整理：2026-09-01

## 题目

10 万人抢 1000 个座位；同一座位优先分配给路程长的用户；同时承受流量并保证高可用。

## 设计要点

```text
网关限流/排队 → Redis 原子预扣 → 消息队列削峰 → 数据库事务确认
                                         ↓
                              超时释放、重试、死信和补偿
```

- Redis Lua 或原子命令完成检查库存、扣减库存、记录用户幂等标记；查询库存只用于展示，最终以扣减结果为准。
- 订单使用全局唯一 ID 和唯一约束防重复；消费、支付回调、库存释放都必须幂等。
- Redis 成功预扣后异步落库；数据库事务确认座位，失败时补偿 Redis 库存。
- 订单超时自动释放座位；失败消息进入重试队列和死信队列。
- Redis 使用主从 + Sentinel 或 Cluster；数据库做最终订单事实来源，并准备故障转移和数据校验。

## 长距离优先与公平性

将距离映射为优先级，使用优先级队列或 ZSet 调度；同时加入等待时间衰减或配额轮转，避免长距离请求持续涌入导致中短距离用户饥饿。若座位与路线有关，应由统一调度器基于起终点和座位区间分配，不能让多个消费者各自抢同一座位。
