


#### 执行链
##### 旧版
* **UsernamePasswordAuthenticationFilter**:  负责处理我们在登陆页面填写了用户名密码后的登陆请求。入门案例的认证工作主要有它负责。
* **ExceptionTranslationFilter：** 处理过滤器链中抛出的任何AccessDeniedException和AuthenticationException 。
* **FilterSecurityInterceptor：** 负责权限校验的过滤器。

##### 新版
- **SecurityContextHolderFilter**：加载已有登录态，供后续过滤器判断当前用户是谁；请求结束时清理当前线程的安全上下文，不会删除 Session 中的登录态。
- **UsernamePasswordAuthenticationFilter**：处理用户名密码登录请求，交给 AuthenticationManager 校验；成功后保存登录态并执行成功处理器，失败则执行失败处理器。普通业务请求直接继续。
- **AnonymousAuthenticationFilter**：没有认证信息时，为当前请求设置匿名身份。
- **ExceptionTranslationFilter**：先放行执行后续过滤器，再捕获下游抛出的 AuthenticationException 和 AccessDeniedException；未登录则引导登录或返回 401，已登录但权限不足通常返回 403。它不会捕获整条链的所有异常。
- **AuthorizationFilter**：新版默认代替 FilterSecurityInterceptor，检查访问权限；允许则放行，否则抛出异常，由前面的 ExceptionTranslationFilter 处理。
- **Controller**：安全检查通过后，执行业务方法。

> 以上是核心流程，省略了 CSRF、退出登录等过滤器。登录请求通常在认证成功或失败处理器中直接返回，不会继续到 Controller。
>
> 登录认证解决“你是谁”；后续业务请求通常加载已有登录态，再通过授权检查判断“你有没有权限”。

#### 过滤器链

![[Pasted image 20260919022935.png|558]]


|顺序|过滤器|主要作用|
|---|---|---|
|1|`DisableEncodeUrlFilter`|禁止通过 URL 重写携带 Session ID|
|2|`WebAsyncManagerIntegrationFilter`|在 Spring MVC 异步处理场景中传递安全上下文|
|3|**`SecurityContextHolderFilter`**|加载安全上下文，请求结束时清理线程中的上下文|
|4|`HeaderWriterFilter`|写入安全相关响应头|
|5|`CsrfFilter`|校验需要 CSRF 防护的请求|
|6|`LogoutFilter`|处理退出登录|
|7|**`UsernamePasswordAuthenticationFilter`**|处理表单用户名、密码登录，默认匹配 `POST /login`|
|8|`DefaultResourcesFilter`|提供默认登录界面所需的静态资源|
|9|`DefaultLoginPageGeneratingFilter`|生成默认登录页|
|10|`DefaultLogoutPageGeneratingFilter`|生成默认退出确认页|
|11|`BasicAuthenticationFilter`|处理 HTTP Basic 认证|
|12|`RequestCacheAwareFilter`|在匹配时恢复之前缓存的请求|
|13|`SecurityContextHolderAwareRequestFilter`|让 Servlet 的用户、角色相关 API 接入 Security|
|14|`AnonymousAuthenticationFilter`|没有认证信息时，提供匿名身份|
|15|**`ExceptionTranslationFilter`**|将下游认证、授权异常转换为登录引导或拒绝响应|
|16|**`AuthorizationFilter`**|根据授权规则判断是否允许访问|
