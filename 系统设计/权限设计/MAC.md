# MAC：系统按照安全等级强制判断

MAC 全称是 **Mandatory Access Control**，中文叫强制访问控制。

先记一句话：

> 系统给用户和资源标上安全等级，然后按照统一规则强制判断，资源主人也不能私自放行。

## 一、先看一个真实例子

某单位把安全等级分成：

```text
1 = 普通
2 = 秘密
3 = 机密
4 = 绝密
```

张三的安全等级是 3，李四的安全等级是 1。

系统里有两份文件：

```text
文件 1001：《日常通知》，等级 1
文件 1002：《机密计划》，等级 3
```

查看文件时，系统规定：

```text
用户等级 >= 文件等级，才允许读取。
```

于是：

```text
张三等级 3 >= 文件 1002 等级 3，可以看
李四等级 1 < 文件 1002 等级 3，不可以看
```

即使文件的创建者愿意发给李四，系统仍然拒绝。这就是“强制”。

## 二、MAC 和 DAC 的根本区别

DAC 问的是：

```text
资源主人愿不愿意把权限给你？
```

MAC 问的是：

```text
系统规定你的安全级别够不够？
```

DAC 的决定权主要在资源主人手中；MAC 的决定权在系统安全规则手中。

## 三、最简单需要保存哪几类信息

MAC 是一种思想，不强制规定必须有固定数量的表。

最简单只需要保存：

```text
1. 用户的安全等级
2. 资源的安全等级
```

可以直接把等级字段放进用户表和文件表。

### 1. 用户数据

| id | username | security_level |
| ---: | --- | ---: |
| 1 | zhangsan | 3 |
| 2 | lisi | 1 |

逐行翻译：

```text
张三的安全等级是 3（机密）
李四的安全等级是 1（普通）
```

### 2. 文件数据

| id | file_name | security_level |
| ---: | --- | ---: |
| 1001 | 日常通知 | 1 |
| 1002 | 机密计划 | 3 |

逐行翻译：

```text
日常通知要求等级 1
机密计划要求等级 3
```

这里不需要保存“张三能看文件 1002”这种逐人名单。系统可以通过两个等级现场算出答案。

## 四、两张表是什么关系

它们通常没有 `user_id`、`file_id` 这样的关系表连接，而是在请求到来时比较两个字段：

```text
sys_user.security_level
              │
              │ 比较大小
              ▼
secure_file.security_level
```

关系不是“提前给每个人配权限”，而是：

```text
用户带着自己的等级，请求一个带有等级的文件。
系统用固定公式比较两个等级。
```

## 五、一次请求怎么判断

李四请求查看机密计划：

```text
userId = 2
fileId = 1002
action = READ
```

系统判断：

```text
查出李四的等级：1
查出机密计划的等级：3
套用读取规则：1 >= 3 吗？
不成立，所以拒绝。
```

张三请求查看同一文件：

```text
张三等级 3 >= 文件等级 3
= 允许
```

## 六、最简单的建表 SQL

```sql
CREATE TABLE sys_user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(64) NOT NULL,
    security_level INT NOT NULL
);

CREATE TABLE secure_file (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    file_name VARCHAR(100) NOT NULL,
    security_level INT NOT NULL
);
```

数字越大表示安全等级越高，这是本例自己的约定，不是 MAC 强制要求的写法。

## 七、插入示例数据

```sql
INSERT INTO sys_user (id, username, security_level) VALUES
(1, 'zhangsan', 3),
(2, 'lisi', 1);

INSERT INTO secure_file (id, file_name, security_level) VALUES
(1001, '日常通知', 1),
(1002, '机密计划', 3);
```

## 八、最核心的查询 SQL

判断用户 2 能否读取文件 1002：

```sql
SELECT 1
FROM sys_user u
JOIN secure_file f ON f.id = 1002
WHERE u.id = 2
  AND u.security_level >= f.security_level
LIMIT 1;
```

把 SQL 翻译成人话：

```text
取用户 2 和文件 1002，
如果用户等级大于或等于文件等级，就返回一行。
有结果表示允许，没有结果表示拒绝。
```

## 九、MAC 适用场景

* 军事和涉密系统。
* 政府机密文件管理。
* 对数据分级要求严格的金融或科研系统。
* 必须由中央安全策略统一控制的系统。

普通后台管理系统通常以 RBAC 为主，不会单独使用完整的 MAC。

## 十、高级扩展：读取和写入可能不是同一条规则

为了防止机密信息向低等级泄露，经典模型可能规定：

```text
读取：不能向上读
用户等级 >= 资源等级才能读取

写入：不能向下写
用户等级 <= 资源等级才能写入
```

例如等级 4 的用户能读取等级 1 的文件，但不能随便把绝密内容写进等级 1 的普通文件，否则低等级用户就能间接看到绝密内容。

这属于 Bell-LaPadula 等模型的深入规则。面试手写基础 MAC 时，先把“用户标签 + 资源标签 + 系统强制比较”说清楚。

实际系统还可能加入部门、项目等分类标签：等级相同但分类不匹配时仍然拒绝。

## 十一、面试时怎么说

> MAC 是系统基于用户和资源的安全标签进行强制控制。最简单可以在用户表和资源表中分别保存 security_level，请求到来时按照系统规则比较等级。权限不是资源主人自由授予的，所以即使主人同意，安全标签不匹配时系统也会拒绝。
